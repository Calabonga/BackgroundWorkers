## Рекомендации по языку C# и стилю

Проект собирается под `netstandard2.1` с `<LangVersion>8.0</LangVersion>`. Эти правила **заменяют** общие правила из `C:\Projects\.claude\rules\code-styles.md` там, где они противоречат ограничениям C# 8.0.

### **Синтаксис C# 8.0**
- Используй блочные пространства имён (`namespace X { ... }`) — file-scoped namespaces недоступны.
- Не используй `global using`, `record`, `init`, `is not`/`and`/`or`-паттерны, target-typed `new()` — всё это C# 9+.
- Доступно и приветствуется: `using var`, `switch`-выражения, property/tuple-паттерны, `??=`, статические локальные функции.

### **Безопасность нулевых значений**
- `<Nullable>enable</Nullable>` включён.
- Не используй `!` для подавления предупреждений, если это не задокументировано. Существующий `_schedule!` в `ScheduledHostedServiceBase.ExecuteAsync` оправдан тем, что поле заполняется в конструкторе.

### **Стиль написания кода**
- Используй `var` для локальных переменных, когда тип очевиден из правой части выражения.
- Применяй `nameof()` вместо строковых литералов для именования методов, свойств и событий.
- Применяй `is` и `as` вместо приведения типов.
- Новые свойства типа `bool` называй с префиксом `Is` или `Has`. Существующее `IncludingSeconds` не переименовывай — это публичный контракт.
- Используй `switch`-выражения вместо `switch`-операторов и цепочек `if-else`, когда это возможно.
- Используй `try-catch` только для ожидаемых ошибок, а не для управления потоком выполнения.
- Явно указывай модификаторы доступа для всех членов класса.
- Члены, не предназначенные для наследников, объявляй `private`. Точки расширения — `protected virtual`/`protected abstract`.
- Базовые классы воркеров — `abstract`. Прочие классы (исключения, вспомогательные типы) помечай `sealed`, если наследование не требуется.
- Порядок членов класса: private-поля → конструкторы → публичные свойства и методы → private-методы → override-методы → `Dispose()`/`DisposeAsync()`.
- Документируй `public`/`protected` члены XML-комментариями (`/// <summary>`): это пакет NuGet.

### **Асинхронный поток**
- Добавляй `Async` ко всем именам асинхронных методов.
- В новом и изменённом коде используй `ConfigureAwait(false)` — это библиотечный код.
- Передавай `CancellationToken` во все асинхронные методы, которые его принимают, включая `Task.Delay`.

### **Обработка ошибок**
- Используй подход Fail Fast: некорректная конфигурация воркера (например, пустой `Schedule`) приводит к исключению в конструкторе.
- Для ошибок конфигурации используй исключения из `Exceptions/` (`WorkerArgumentNullException`); новые — по той же схеме `Worker*Exception`.
- Шаблон `Result` (`Calabonga.Results`) здесь не применяется: у библиотеки нет бизнес-потоков.
- Исключения из пользовательского `ProcessInScopeAsync` не должны останавливать воркер — сохраняй текущее поведение «залогировать и продолжить».

### **Логирование**
- Библиотека получает `ILogger` от наследника через конструктор — не создавай логгеры сама.
- В новом коде используй шаблоны сообщений (`Logger.LogInformation("{DisplayName} started", DisplayName)`), а не интерполяцию строк.
- Уровни: `Error` — исключение в итерации, `Information` — старт/значимые события. Не логируй каждую итерацию цикла.

### **Время/Часы**
- Сейчас используется `DateTime.Now` (локальное время сервера). `TimeProvider` в `netstandard2.1` доступен только через пакет `Microsoft.Bcl.TimeProvider` и меняет конструкторы — вводи его только после согласования.
- Не смешивай `DateTime.Now` и `DateTime.UtcNow` в расчётах `NextRun`.
